This catalog separates current product behavior from examples of what bounded automation could support.

| Status | Meaning |
| --- | --- |
| Live | Available through the current supported product path. |
| Pilot | Available only to a named, bounded pilot. |
| Illustrative | The control model could express the workflow, but Loyal is not claiming a product or roadmap commitment. |
| Unsupported | A required product or protocol dependency does not exist in the current system. |

| Automation | Status | Boundary |
| --- | --- | --- |
| Balance Sweep & Earn | Live | Keep a reserve, sweep eligible USDC, and route it through an approved USDC Earn path. |
| Customer subscription billing | Illustrative | Would require a separate customer-approved payment policy and product flow. |
| Settlement routing | Illustrative | Would require a defined settlement trigger, destination, reconciliation model, and exit. |
| Treasury allocation | Illustrative | Would require approved destinations, limits, risk ownership, and current deployment evidence. |
| Automatic withdrawal before a future payment | Unsupported | Loyal does not currently predict a payment and return funds before it occurs. |

Status changes only when the implementation path and supported customer experience are verified.
