Loyal Smart Accounts are programmable Solana accounts for teams and apps that need shared control, policy-based execution, or a safer operational boundary than one wallet can provide.

Loyal's SDKs target the Squads Smart Account Program. This section documents the Loyal developer surface.

## When to use a Smart Account

Use Loyal Smart Accounts when you need one or more of these:

- Multiple signers with an approval threshold
- A controlled separation between configuration and funds
- Proposal-based execution with an optional delay
- Rules around what can be spent or executed
- A TypeScript SDK, with a narrower Rust surface for create flows

<Info>
If you only need a single signer wallet with no policy logic, Smart Accounts are probably unnecessary overhead.
</Info>

## Mental model

Think about the system in five pieces:

| Piece | What it does |
| --- | --- |
| `Settings` | The configuration root for a Smart Account |
| Sub-accounts and vaults | The addresses that hold assets and execute |
| Signers + permissions | Who can initiate or vote, and who can execute |
| Transactions + proposals | The async governance path |
| Policies | Scoped rules for what can happen and under what limits |

Use [Concepts](/smart-accounts/concepts) for the exact account vocabulary. Use [Policies and execution](/smart-accounts/policies-and-execution) to choose the execution mode. The directory below links to frontend and SDK implementation.
